# Memo: Kube Copilot Project (KC)

Michael Tanner, April 25, 2025

## 1. Purpose  
Kube Copilot (abbreviated **KC**) aims to let engineers interact with Kubernetes and related tooling through natural-language chat. The project is fully open-source and currently hosted on GitHub (at `kubecopilot.net` and `https://github.com/michael-tanner/kube-copilot`).

## 3. Current State  
| Area | Status |
|------|--------|
| **Language** | Go |
| **Execution** | Optimized for a VS Code **dev-container**; uses a Docker image with all required CLIs. |
| **CLI** | `kc` command works for basic queries (e.g., “List namespaces and running pods”). |
| **Dependencies** | `kubectl`, Helm (integration pending). |
| **Backend API** | Serves the CLI today; designed to power a future web UI. |
| **Project structure** | `.kubecopilot/` folder holds a YAML config plus a `workspace/` sub-folder for local files. |

## 4. Immediate Roadmap  
1. **File-System Integration**  
   - Finalize API functions that read/write the `.kubecopilot/workspace` files.  
   - Extend LLM tools to use those functions.

2. **Helm Support**  
   - Enable chat-driven Helm installs/upgrades of popular charts.  
   - Refresh knowledge of Helm workflows and edge cases.

3. **Testing Strategy**  
   - **Unit tests**: expand coverage with Go test suites.  
   - **Integration tests**:  
     - Spin up a lightweight Kubernetes cluster (kind or minikube) in GitHub Actions.  
     - Inject an OpenAI API key securely.  
     - Ensure tests tear down resources to control costs.

4. **Web Interface**  
   - Build a static React front-end that communicates with the REST API.  
   - Host either from the cluster or locally via the same dev container.

## 5. Longer-Term Ideas  
- **End-to-End Dev Workflow**  
  - Let the LLM clone repos, modify code, build Docker images, and deploy them into a dedicated dev node, then run tests and open pull requests automatically.

- **Dapr & Radius Integration**  
  - Explore how KC can bootstrap Dapr or Microsoft Radius components, giving users opinionated patterns for microservices and platform engineering.

- **Security & Observability**  
  - Plug in security-scanning tools such as **Drasi** (Max Loeffler’s project in Rust) for continuous change monitoring.  
  - Evaluate Grafana’s free tier for dashboards and alerts.

- **Copilot into devcontainer on local/remote machine**
  - This idea is forward looking and aims to allow KubeCopilot to be the driver in another container instance running
  a local devenviornment. This way KubeCopilot has locus of control, yet the human pilot would see and approve code changes in a local instance of VS Code.
  - With a full-features KubeCopilot Web UI, this would also work with cloud-based devcontainer images.

## 6. Open Questions

2. Establish testing enviornments in Azure and AWS while keeping costs low.
